**Title**:
[PR Feedback] Navigation Edge Routing

**Description**:
Based on consolidated PR review, address the following in **Navigation Edge Routing**:

- **Channel-based circuit-trace router replaced with generic obstacle-avoidance router**: The architect spec's `channelRouter.ts` design centers on extracting explicit routing channels from tree layout row/column gaps and routing edges through those channels with 90° turns at intersections — explicitly called superior to general A* because the tree layout guarantees channels exist. The implemented `src/utils/channelRouter.ts` contains no channel-extraction step or channel data structure; `routeNavigationEdge`/`buildOrthogonalPath` performs generic per-edge obstacle-avoidance against bounding boxes with L-shaped path fallback. The public API signature also differs from the spec. (`src/utils/channelRouter.ts`)
- **Navigation edges route around structural edges instead of over them**: The parent issue specifies navigation edges should be "visually routed as a circuit trace which routes … over other edges." The implementation builds bounding-box obstacles from every structural edge path and passes them to `routeNavigationEdges`, so routes are steered to avoid crossing structural edges entirely rather than being drawn crossing over them as specified. (`src/components/GraphCanvas.tsx`, `src/utils/channelRouter.ts`)
- **Nudge pass does not propagate offsets to connected perpendicular segments**: The spec requires a corner-adjustment step that shifts a perpendicular segment's endpoint when an adjacent segment is nudged, preserving 90° joints. `nudgeOverlappingSegments`/`nudgeHorizontalSegment`/`nudgeVerticalSegment` groups by rounded coordinate and only shifts endpoints of the two overlapping segments — it does not propagate the offset to connected perpendicular segments elsewhere in the same route, so nudged segments can become disconnected from their own polyline at corners. (`src/utils/channelRouter.ts`)
