**Title**:
Phase 1: Popover core primitive component

**Description**:
Add a new standalone `Popover` compound component (`Popover` / `Popover.Trigger` / `Popover.Panel`) to the component library, implementing the WAI-ARIA non-modal dialog/disclosure pattern. This is the foundational primitive that later phases wire into `GraphCanvas`. It is intentionally separate from `Tooltip` — different trigger mechanism (click/Enter/Space vs. hover), different dismiss behavior (Escape/outside-click vs. pointer-leave), different ARIA role (`dialog` vs. `tooltip`), and support for interactive children.

## Requirements
- New `Popover` component exported from `src/index.ts` alongside `Tooltip`, with `PopoverProps` and `PopoverPlacement` types
- Compound API: `Popover` (root, manages open state via context), `Popover.Trigger` (binds click + Enter/Space + ARIA to its child), `Popover.Panel` (positioned, focus-trapped, interactive overlay)
- Panel content is never rendered inside an `aria-hidden` ancestor while open
- Trigger and panel are programmatically associated via ARIA: `aria-haspopup="dialog"`, `aria-expanded`, `aria-controls` on the trigger; `role="dialog"` on the panel
- Supports both controlled (`open` + `onOpenChange`) and uncontrolled (internal state) usage, matching `Tooltip`'s existing controlled/uncontrolled pattern
- Opens via click and via keyboard activation (Enter/Space) on the trigger
- Dismisses via Escape key and via click outside both trigger and panel
- No dismiss-on-pointer-leave — interactive content (links, buttons) inside the panel remains usable without the panel closing
- On close, focus returns to the triggering element
- Supports edge-aware positioning/flipping (`top`/`bottom`/`left`/`right`, default `bottom`) consistent with `Tooltip`'s existing flip logic
- Visually and semantically distinct from `Tooltip` (does not reuse `role="tooltip"`)
- A Popover section is added to the appropriate `src/test-pages/` page for Playwright visual regression coverage

## Design Guidance
Implements the "Popover Component" architecture — the compound-component topology (`Popover` / `Popover.Trigger` / `Popover.Panel`), the ARIA pattern table, focus management via the existing `useFocusTrap(..., { mode: 'popup' })` hook (already used by `MapCanvas.PinPopover`), the three dismiss paths, and the CSS-relative placement/flip system shared with `Tooltip`. Corresponds to "Phase 1: Popover Component" in the architecture's Implementation Plan (`Popover.tsx`, `Popover.css`, `src/index.ts` exports, test page).

## Acceptance Criteria
- [ ] `Popover`, `Popover.Trigger`, `Popover.Panel` are implemented and exported from `src/index.ts` with TypeScript prop types
- [ ] When open, the panel is not a descendant of any `aria-hidden="true"` element
- [ ] Trigger has `aria-haspopup="dialog"`, `aria-expanded` toggling true/false, and `aria-controls` pointing at the panel's id when open; panel has `role="dialog"`
- [ ] Clicking the trigger, and pressing Enter or Space while the trigger is focused, opens the panel
- [ ] Pressing Escape while the panel is open closes it and returns focus to the trigger
- [ ] Clicking outside the trigger and panel closes the panel
- [ ] A focusable link/button placed inside `Popover.Panel` can be clicked or tabbed to and activated without the panel closing
- [ ] Panel correctly flips placement near a viewport edge, matching `Tooltip`'s existing flip behavior
- [ ] Both controlled (`open`/`onOpenChange`) and uncontrolled usage work as documented
- [ ] New Playwright visual regression snapshots exist for each placement and for a panel containing interactive content
- [ ] Code is reviewed and approved
