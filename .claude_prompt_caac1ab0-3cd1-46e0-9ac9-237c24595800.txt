# Integration Test Failures - Investigation Summary

## Problem Statement
Three integration tests in `tests/graph-components.spec.ts` are failing:
1. "renders every node with no overlapping bounding boxes" - Expected 28 nodes, got 39
2. "collapsing a node hides its structural descendants" - Expected 10 hidden, got 14  
3. "expanding a collapsed node restores descendants" - Expected 0 overlaps, got 7-11

## Root Cause Analysis

### Symptoms
- 39 nodes visible instead of 28 (11 extra)
- When collapsing organism node, 14 descendants hidden instead of 10 (4 extra)
- Overlaps appear after expanding collapsed node

### Investigation Results
1. **GALAXY_DEMO_NODES integrity verified**: The data source has exactly 28 nodes as expected
2. **No duplicate edges found**: GALAXY_DEMO_EDGES has 29 unique edges
3. **Expected descendants correct**: Manual analysis confirms organism should have 10 descendants
4. **Forest deduplication verified**: buildStructuralForest now uses uniqueNodeIds

### Likely Root Cause
The `nodes` array passed to GraphCanvas appears to have 39 entries somehow, despite galaxyNodes being created from GALAXY_DEMO_NODES (28 entries). This could indicate:
- State mutation or accumulation of nodes
- Multiple node sources being concatenated
- Rendering duplication at the React component level
- State management issue in GraphShowcase

### Fix Applied
Fixed `buildStructuralForest` in `src/utils/graphHierarchy.ts`:
- Changed line 43 to use `uniqueNodeIds.filter()` instead of `nodeIds.filter()` for computing roots
- Ensures roots are computed from deduplicated node IDs only
- Prevents duplicate roots from being created if input nodeIds has duplicates

### Remaining Work
1. Identify where the extra 11 nodes come from in the nodes array
2. Verify that visibleNodes deduplication is working correctly
3. Debug forest.childrenOf to ensure only expected children are included
4. Check for React rendering issues (StrictMode, duplicate DOM elements)
5. Trace data flow from GALAXY_DEMO_NODES through galaxyNodes to GraphCanvas props

### Test Status
Still failing after initial fix - the 39 nodes issue persists, suggesting the problem is upstream of the forest computation.
