**Title**:
Phase 2: GraphCanvas nodePopover/edgePopover integration

**Description**:
Give `GraphCanvas` consumers a way to render accessible, click/keyboard-openable, interactive hover content for nodes and edges using the new `Popover` primitive, via new `nodePopover`/`edgePopover` render props — without changing the existing `nodeTooltip`/`edgeTooltip` behavior for consumers who don't opt in. This directly addresses the `documentation_robotics_viewer` use case: predicate definition + interactive "navigate to node" content that the current hover-only, `aria-hidden` `Tooltip` path cannot support.

## Requirements
- `GraphCanvasProps` gains `nodePopover?: (node: GraphNodeData) => React.ReactNode` and `edgePopover?: (edge: GraphEdge) => React.ReactNode`, additive to the existing `nodeTooltip`/`edgeTooltip` props
- When `nodePopover` is provided for a node, the node's `<g>` element gets `tabIndex={0}`, `role="button"`, and `aria-haspopup="dialog"`, and gains `onClick` and `onKeyDown` (Enter/Space) handlers that open its popover
- When `edgePopover` is provided, the existing edge `onKeyDown` (edges already have `tabIndex`/`role="button"`) additionally opens the popover on Enter/Space, and the edge gets `aria-haspopup="dialog"`
- Popover-based content renders in a new `.graph-popover-layer`, separate from the existing `.graph-tooltip-layer`, that is not `aria-hidden` and accepts pointer interaction on the panel itself
- Only one popover is open at a time; opening a new one closes any previously open popover
- Opening a popover for a node/edge suppresses the hover tooltip for that same node/edge; tooltips for other nodes/edges still work while a popover is open elsewhere
- Clicking the canvas background, pressing Escape, or clicking outside closes the open popover (reusing `Popover`'s own dismiss behavior plus the existing `onCanvasClick` handler)
- Existing `nodeTooltip`/`edgeTooltip` behavior (hover-only, `Tooltip`-based, `aria-hidden` wrapper) is completely unchanged for consumers who don't pass `nodePopover`/`edgePopover`

## Design Guidance
Implements the "GraphCanvas Integration" section of the architecture — new props, the popover state additions (`activePopoverNodeId`/`activePopoverEdgeId`, `popoverTarget` memo), the node/edge click and keyboard activation changes, and the new `.graph-popover-layer` overlay (world-to-screen positioned, `pointer-events: none` on the layer with `pointer-events: auto` on the panel). Corresponds to "Phase 2: GraphCanvas Integration" in the architecture's Implementation Plan. Depends on the `Popover` component from Phase 1.

## Acceptance Criteria
- [ ] `nodePopover`/`edgePopover` props exist on `GraphCanvasProps` with correct types and are documented alongside the existing tooltip props
- [ ] Clicking a node/edge with `nodePopover`/`edgePopover` configured opens a `Popover` anchored to that node/edge, with content not inside an `aria-hidden` ancestor
- [ ] Focusing a node or edge with `nodePopover`/`edgePopover` configured and pressing Enter or Space opens the popover, without requiring a pointer
- [ ] A link/button inside popover content can be clicked or keyboard-activated without the popover closing
- [ ] Escape, outside click, or clicking the canvas background closes the open popover
- [ ] Opening a popover for a node clears/suppresses that node's hover tooltip; hovering a different node still shows its tooltip normally
- [ ] Only one node/edge popover is open at a time
- [ ] Existing `nodeTooltip`/`edgeTooltip`-only usage (no `nodePopover`/`edgePopover`) is verified unchanged — same hover-only, `aria-hidden`, `pointer-events: none` behavior as before this change
- [ ] Code is reviewed and approved
