[PR Feedback] ARIA / Accessibility

**Description**:
Based on consolidated PR review, address the following in **ARIA / Accessibility**:

- **`aria-describedby` applied on `aria-hidden="true"` non-interactive edges**: `GraphEdgeInternal` line 314 unconditionally spreads `aria-describedby` when `tooltipId` is truthy, but line 309 sets `aria-hidden={true}` on non-interactive edges (those without `onEdgeSelect` or `edgePopover`). Setting `aria-describedby` on an `aria-hidden` element is semantically contradictory — assistive tech ignores the element entirely, so the ARIA association is dead. ARIA validators (axe, Lighthouse) will flag this. The JSDoc on `nodeTooltipTrigger` (line 413) also incorrectly claims the association holds for all hover tooltips, which doesn't apply to non-interactive edges. Fix: gate the spread on the `interactive` flag. (`src/components/GraphCanvas.tsx:314`)
- **Unsanitized entity IDs used as HTML `id` attributes in tooltip association**: `nodeTooltipId` and `edgeTooltipId` (lines 53–56) do raw string interpolation (`tooltip-node-${nodeId}`). If a consumer passes an ID containing spaces, the generated `id` is invalid HTML and `aria-describedby` silently splits into multiple non-existent ID references with no error. `GraphNodeData.id` is typed as plain `string` with no documented constraint; current test data uses safe snake_case but the contract is unguarded. (`src/components/GraphCanvas.tsx:53-56`)
