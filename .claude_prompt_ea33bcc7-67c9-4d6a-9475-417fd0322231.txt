[PR Feedback] GraphCanvas Layout Integration

**Description**:
Based on consolidated PR review, address the following in **GraphCanvas Layout Integration**:

- **Structural vs navigation edge separation broken when `isStructuralEdge` not supplied**: In the ux-navigation layout branch (~line 276), every edge's structural flag comes from `safeIsStructuralEdge`, which defaults to `true` for all edges when `isStructuralEdge` is omitted. The PR's own test page passes `isPageNode` and `isNavigationRoute` but never `isStructuralEdge`, so navigation-route edges (including cross-tree ones like `page1→page2`) are fed into `buildStructuralForest` as hierarchy edges, creating parent-cycles and misattaching children. The committed baseline screenshots confirm the tree structure is non-functional. `src/components/GraphCanvas.tsx:~276, ~187`
- **Auto-center/fitView effect missing `ux-navigation` guard**: The auto-center effect guards against premature centering for `force`, `galaxy`, and `force-clustered` layouts but omits `ux-navigation`. The effect fires before `computedPositions` is populated, frames a degenerate bounding box (all nodes at fallback origin), sets `didCenterRef.current = true`, and never retries — the graph renders zoomed into the origin. `src/components/GraphCanvas.tsx:~1370`
- **Obstacle filter uses broken reference equality**: `nodeRects.filter(r => r !== src && r !== tgt)` uses reference equality, but `getNodeRect` returns a fresh object per call. The filter never excludes source/target nodes, so `routeNavigationEdge` treats them as obstacles and produces unnecessary detours. `src/components/GraphCanvas.tsx:~249`
- **Non-null assertion on `nodeMap.get(node.id)!` can crash**: In the ux-navigation layout branch, `(node) => pageNode(nodeMap.get(node.id)!)` passes `undefined` to the consumer's `isPageNode` callback if there is any mismatch between `nodes` (used to build the map) and `layoutNodes` (built from `visibleNodes`). `src/components/GraphCanvas.tsx:~1143`
- **`isNavigationRoute` and `isPageNode` callbacks lack safety wrappers**: Every other user-provided predicate has a try-catch wrapper (e.g., `safeIsStructuralEdge`). The two new callbacks have none across 4 call sites — a throwing predicate crashes the component with no error surfaced. `src/components/GraphCanvas.tsx:~2363, ~936, ~1143`
- **`isNavigationRoute` effects not layout-gated despite JSDoc claim**: JSDoc says "Only meaningful with layout='ux-navigation'", but matching edges get orthogonal routing and the `graph-edge--navigation` CSS class regardless of layout. A consumer passing `isNavigationRoute` with `layout="force"` gets unexpected visual changes. `src/components/GraphCanvas.tsx:~565`
