Based on consolidated PR review, address the following in **StackedBar**:

- **`stackLabel='total'` renders literal "NaN" for stacks with NaN parts**: In `StackedBar.tsx:115`, if any element in `stack.parts` is `NaN`, the `reduce` sum produces `NaN` and `fmt(NaN)` returns the string "NaN" as user-visible label text. Additionally, `Math.max(...totals)` becomes `NaN`, and the `hi || 1` fallback silently distorts the Y-axis scale for all other stacks.
- **Zero-sum `stackLabel` bug fix (commit 38c418f) has no regression test**: The fix changed `fmt(total)` to `fmt(totals[si])` to display "0" instead of "1" for zero-sum stacks, but test data (`STACKS` in `ChartsTestPage.tsx`) contains only non-zero stacks. A future refactor could revert this fix undetected.
- **`stackLabel` text is not positioned above each bar's actual height**: In `StackedBar.tsx:113`, the label uses a fixed `y={pad.top - 6}` for every stack instead of the spec-required `y={yAt(totals[si]) - 6}`. Labels only appear correct for the tallest bar; for shorter stacks, the label floats at a constant height disconnected from the bar's top, contradicting the explicit per-bar positioning in the implementation plan.
