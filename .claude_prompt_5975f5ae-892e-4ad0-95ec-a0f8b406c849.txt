Based on consolidated PR review, address the following in **GraphCanvas Hover State Management**:

- **`onNodeHover`/`onEdgeHover` callbacks lack try/catch protection**: `src/components/GraphCanvas.tsx:451-456` — these consumer callbacks run inside `useEffect`, where an uncaught error crashes the React tree. The PR wraps render-phase callbacks (`renderEdge`, `nodeTooltip`, `edgeTooltip`) in try/catch but not these effect-phase callbacks — an inconsistent safety boundary.
- **Stale hover cleanup for collapsed nodes is untested**: `src/components/GraphCanvas.tsx:601-612` clears `hoveredNodeId` when the hovered node is collapsed away. Without this, `onNodeHover` never fires `undefined` and caller state sticks forever — but no test exercises this path, so a regression would be invisible.
- **Stale hover cleanup for removed edges is untested**: `src/components/GraphCanvas.tsx:458-467` clears `hoveredEdgeId` when the hovered edge disappears from `edges`. Same class of bug as the node case — no test covers this path.
